# Convergence: demo video script

**Status:** draft v4.1 (staged recording cells: agents ran earlier today on the deployed Worker; the human steps happen on camera), for the decision owner's approval. Updated for the redesigned console (Work | Map switch, Needs you / Working / Ready / Merged home, item pages) and the new beat order: WI-1 is Held and rejected before the decision changes to v2. Labels match the deployed console (Work, Map, Needs you, Why blocked?, Revalidate, Allow with exception, What it was given, Merge, Audit log). It is final only when it matches what the deployed console does on recording day.
**Target runtime:** 9:00 (the contest allows 5 to 10 minutes; hard ceiling for this script is 9:30). Times are paced at about 150 spoken words a minute plus the on-screen holds marked in each row. A few rows run tight; the edit can hold the last frame.
**Format:** screen recording with voiceover, no music. Narrator and face cam are still open (PRD §13, item 4).

## Naming rule

Say and show "Convergence" every time: narration, on-screen text, titles, captions and copy. Delta is the reconciliation engine inside it, never the product name. Internal identifiers (`refs/notes/delta`, `delta-core`) are fine when they appear as code on screen; do not read them aloud as the product name.

**One exception, segment 11b ("Where this comes from"):** the decision owner names the three ideas behind the project, Strata, Delta and Convergence, as concepts. There, "Delta" alone names the coordination idea, not the product. Name them only as concepts: no repo names, file paths or other projects. Everywhere else the rule above holds.

## Plain-language rule for narration

No "receipt", "stale", "facet", "promote" or "gate" in spoken lines where a plain word works. Button and tab names are read as they appear on screen (Revalidate, Merge, Why blocked?, What it was given). Reason codes such as `NO_DEPENDENCY_ON_CHANGED_FACETS` appear on screen only and are never read aloud.

## Honesty legend

Every segment carries one of these labels. The label appears on screen as a small corner tag whenever it isn't LIVE.

| Label | Meaning |
|---|---|
| **LIVE** | A real run recorded on the day: real agents on the models shown on screen, the deployed Worker, real Artifacts forks. Long agent runs may be sped up; if so, a "4x" tag and a wall-clock overlay are on screen. |
| **LIVE (staged)** | The agents ran for real on the deployed Worker earlier on recording day, and their cell was paused after both pushed. Everything a human does (reject, decision change, revalidate, merge) happens live on camera; a revalidate is a fresh live agent run. Tagged "agents ran earlier today" on screen. |
| **SEEDED** | Synthetic data generated by a fixture, with no model behind it. Always tagged "seeded" on screen. |
| **REPLAY** | A recorded event log re-driven through the same engine. Always tagged "replay" on screen. |
| **GRAPHIC** | Illustration or title card. Not a recording of the product. |

The `/story` deck is GRAPHIC throughout, including its interactive slide: that slide is a small model of the rule over synthetic data, not the engine. Its corner tag stays on screen for every deck slide, and the slide before the live footage shows "next: LIVE" beside it rather than a LIVE tag.

If a live step fails and a fallback goes in, change the on-screen tag and the narration to match. Never present replay as live.
