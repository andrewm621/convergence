# Delta Convergence: demo video script

**Status:** draft v1, written from PRD v1.2 before the build is finished. Revise after M4 (resolve + promote) and again after M6 (ship). It is final only when it matches what the deployed console actually does on recording day.
**Target runtime:** 7:55 (the contest allows 5 to 10 minutes).
**Format:** screen recording with voiceover. Narrator and face cam are still open (PRD §13, item 4).

## Honesty legend

Every segment carries one of these labels. The label appears on screen as a small corner tag whenever it isn't LIVE.

| Label | Meaning |
|---|---|
| **LIVE** | A real run recorded on the day: real Claude agents, the deployed Worker, real Artifacts forks. Long agent runs may be sped up; if so, a "4x" tag and a wall-clock overlay are on screen. |
| **SEEDED** | Synthetic data generated by a fixture, with no model behind it. Always tagged "seeded" on screen. |
| **REPLAY** | A recorded event log re-driven through the same engine. Always tagged "replay" on screen. |
| **GRAPHIC** | Illustration or title card. Not a recording of the product. |

If a live step fails and a fallback goes in, change the on-screen tag and the narration to match. Never present replay as live.

## Recording-day checklist

**Before the first take**
- [ ] Deployed URL loads. Header reads "Acting as: Andrew (demo identity)". Theme and window size fixed.
- [ ] Scenario A reset: `notifications` v1, `status-model` v1, ledger empty, no leftover forks.
- [ ] Scenario B replay log loaded; seeded fan-out fixture generated (40 items).
- [ ] Scratch clone of the baseline ready for the control shot, with each fork's tests runnable.
- [ ] Terminal ready for `git notes --ref=delta show`.
- [ ] Models pinned, task prompts fixed, API gateway working.
- [ ] No tokens, account identifiers or private paths visible in any terminal title, tab, URL bar or stream output. Hide the bookmarks bar.

**Cue points (Scenario A)**
1. Start both agents. Wait about 20 s so both are visibly mid-run.
2. Typo commit (prose only). Wait for the `PROSE_ONLY` ledger line.
3. v2 commit (opt-in, weekly digest) while Agent B is still running. This is the guaranteed mid-flight window.
4. Wait for WI-2 to finish. Confirm the claim conflict and TestFailed both appear before moving on.
5. Scratch merge, then WI-1 promote, then Revalidate, then Promote.

**Live risks and fallbacks**

| Risk | Fallback |
|---|---|
| Agent B doesn't produce the conflict | R8 contract test still fails against the code default; narrate that. Otherwise take two, tagged "recorded earlier" |
| Agent skips claims | `NoClaims` condition plus the failing contract test; narrate it |
| Push events lag | Polling is already the primary path; edit out the dead air |
| Sandbox misbehaves | Local runner pushes to the same forks; change the wording on screen and in the narration |
| Revalidate run is slow or loops | Sped-up footage with overlay, or REPLAY tagged as such |
| Promote hits a stale ref | Show the retry on screen |

**Take plan:** two full takes. Keep take two's footage as the tagged fallback for each live beat. Any substituted shot gets its tag.

**Pre-submit pass:** compare every sentence here against the README "Implemented vs not" table and the passing tests; cut or fix anything that doesn't match. The full claims list is in `submission-copy.md`.
